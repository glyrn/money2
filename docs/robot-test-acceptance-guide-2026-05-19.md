## 1. 核心结论

前端访问时不需要传“机器人 uid”。需要传的是 URL 参数 `robot`，表示本局要自动补入几个机器人。

机器人 uid 由服务端自动生成，前端不用关心。当前服务端生成规则是基于房间桌号和座位号生成稳定 uid，并把机器人显示为 `机器人1`、`机器人2` 等。

机器人参数链路如下：

```text
浏览器访问链接里的 query 参数
-> 前端保存完整 window.location.href
-> 前端 LOGIN 时传给服务端 lanuch_url
-> 服务端从 lanuch_url 解析 robot 和 auto_ready
-> 服务端补机器人入座、准备、自动出手
```

注意：代码里字段名是历史拼写 `lanuch_url`，测试人员不需要手动加这个参数。

## 2. 通用造链公式

推荐格式：

```text
{游戏访问地址}?uid=真人用户ID&name=测试昵称&score=初始分&room=房间号&游戏参数...&robot=机器人数量&auto_ready=1
```

示例：

```text
{五子棋访问地址}?uid=10001&name=tester&score=1000&room=qa_wzq_001&play_mode=1&play_count=1&robot=1&auto_ready=1
```

通用要求：

| 参数 | 是否必填 | 含义 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `uid` | 测试必填 | 真人玩家 ID | `10001` | 同一房间内每个真人必须不同；重复 uid 可能触发重连逻辑 |
| `name` | 测试必填 | 真人玩家昵称 | `tester` | 如使用中文或特殊字符，建议 URL 编码 |
| `score` | 建议填写 | 初始分 | `1000` | 部分游戏结算展示会使用 |
| `room` | 必填 | 房间号 | `qa_wzq_001` | 同一个 room 表示进入同一桌；每轮验收建议换新 room |
| `robot` | 机器人测试必填 | 要补入的机器人数量 | `1` | 不是机器人 uid；不传或传 `0` 表示不补机器人 |
| `auto_ready` | 强烈建议 | 自动准备 | `1` | `1` 或 `true` 会让真人和机器人自动准备，更适合验收 |
| `ob_uid` | 观察者才用 | 观战用户 ID | `90001` | 带了会走观战逻辑，不建议机器人验收时使用 |
| `gamedomain` | 特殊部署才用 | 指定 Socket 服务域名 | `game.example.com` | 页面地址和 Socket 地址不一致时才需要 |
| `ycdomain` | 平台联调用 | 指定平台校验/结算域名 | `www.woojey.com` | 普通机器人验收不需要 |
| `sign` | 平台正式登录用 | 平台签名 | `xxx` | 平台登录模式才需要；普通机器人验收可不用 |

`robot` 数量规则：

| 游戏 | 推荐 robot | 最大有效 robot | 说明 |
| --- | --- | --- | --- |
| 欢乐五子棋 | `1` | `1` | 双人游戏，1 个真人 + 1 个机器人 |
| 中国象棋 | `1` | `1` | 双人游戏，1 个真人 + 1 个机器人 |
| 斗地主 | `1` 或 `2` | `2` | 三人游戏，推荐 1 个真人 + 2 个机器人 |
| UNO | `1` 到 `3` | `ready_count - 1`，最多 `3` | 总人数由 `ready_count` 决定 |
| 飞行棋 | `1` 到 `3` | `ready_count - 1`，最多 `3` | 总人数由 `ready_count` 决定 |

服务端会把非法数量归一化：不传、`0`、负数、非数字都按 `0` 处理；超过最大值会被限制到最大有效数量。

## 3. 五款游戏测试链接模板

### 3.1 欢乐五子棋

功能：真人进入房间后，服务端自动补 1 个机器人；准备后开局，机器人在自己回合自动落子。

参数：

| 参数 | 含义 | 推荐值 |
| --- | --- | --- |
| `play_mode` | 对战模式 | `1` |
| `play_count` | 局数 | `1` |
| `robot` | 机器人数量 | `1` |
| `auto_ready` | 自动准备 | `1` |

验收链接：

```text
{五子棋访问地址}?uid=10001&name=tester&score=1000&room=qa_wzq_001&play_mode=1&play_count=1&robot=1&auto_ready=1
```

预期现象：

| 步骤 | 预期 |
| --- | --- |
| 打开链接 | 加载完成并进入游戏桌 |
| 入座后 | 出现真人和 `机器人1` 两个玩家 |
| 开局后 | 机器人在自己回合自动落子 |
| 结束条件 | 任意一方五连后结算 |

### 3.2 斗地主

功能：真人进入房间后，服务端自动补齐三人桌；机器人自动准备、叫分、出牌或过牌。

参数：

| 参数 | 含义 | 推荐值 |
| --- | --- | --- |
| `ready_count` | 参与人数 | `3` |
| `base_score` | 底分 | `100` |
| `play_count` | 局数 | `1` |
| `play_mode` | 玩法标识，服务端保存为是否癞子 | `0` |
| `robot` | 机器人数量 | `2` |
| `auto_ready` | 自动准备 | `1` |

验收链接：

```text
{斗地主访问地址}?uid=20001&name=tester&score=1000&room=qa_ddz_001&ready_count=3&base_score=100&play_count=1&play_mode=0&robot=2&auto_ready=1
```

预期现象：

| 步骤 | 预期 |
| --- | --- |
| 打开链接 | 加载完成并进入斗地主桌 |
| 入座后 | 真人 + 2 个机器人，三人桌坐满 |
| 开局后 | 机器人自动参与叫分 |
| 出牌阶段 | 机器人根据规则自动出牌或过牌 |
| 结束条件 | 一方手牌出完后结算 |

| --- | --- | --- |
| `ready_count` | 总参与人数 | `2`、`3` 或 `4` |
| `game_time` | 单局时长，分钟 | `4` |
| `specific_score` | 目标分 | `1000` |
| `robot` | 机器人数量 | `ready_count - 1` |
| `auto_ready` | 自动准备 | `1` |


预期现象：

| 步骤 | 预期 |
| --- | --- |

```text
{飞行棋访问地址}?uid=60002&name=tester&score=1000&room=qa_fxq_002&play_mode=1&ready_count=4&play_count=1&robot=3&auto_ready=1
```

## 4. 验收步骤

按每款游戏执行：

1. 使用手机浏览器或浏览器移动端模拟器打开对应验收链接。
2. 确认加载进度不会卡在 `99.5%`，能进入游戏桌。
3. 确认真人玩家入座成功。
4. 确认机器人玩家自动出现，显示为 `机器人1`、`机器人2` 等。
5. 确认 `auto_ready=1` 后无需手动准备即可开局。
6. 轮到机器人时等待 1 到 3 秒，确认机器人自动操作。
7. 至少完成一次有效机器人动作。
8. 有条件时跑完整局，确认能进入结算或服务端认可的结束流程。

## 5. 通过标准

| 验收项 | 通过标准 |
| --- | --- |
| 页面加载 | 手机访问不再卡 `99.5%`，能进入游戏 |
| 参数识别 | 同一链接里的 `room`、人数、玩法参数被正确使用 |
| 机器人入座 | `robot` 大于 0 时，空位自动出现机器人 |
| 自动准备 | `auto_ready=1` 时真人和机器人自动准备 |
| 自动操作 | 机器人在自己回合自动执行合法动作 |
| 回合守卫 | 非当前回合玩家不能越权操作 |
| 完整流程 | 游戏能正常推进到结算或服务端认可的结束流程 |
| 多局隔离 | 换新 `room` 后不受上一轮测试状态影响 |

## 6. 常见问题排查

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 页面一直加载或不进入游戏 | URL 没有 query 参数，前端没有触发登录流程 | 确认链接里有 `?uid=...&room=...` |
| 只看到真人，没看到机器人 | 没传 `robot` 或 `robot=0` | 加 `robot=1`、`robot=2` 或 `robot=3` |
| 坐满但不开局 | 没传 `auto_ready=1`，或人数参数不匹配 | 加 `auto_ready=1`，核对 `ready_count` |
| 进入了观战，不是玩家 | 链接带了 `ob_uid` | 机器人验收链接不要带 `ob_uid` |
| 多个测试互相影响 | 多人使用同一个 `room` 或同一个 `uid` | 每轮换新 `room`，每个真人用不同 `uid` |
| 机器人数量不等于传入值 | 超过了游戏可用座位或最大上限 | 按各游戏最大有效 robot 取值 |
| 正式域名连不上 Socket | 前端 `serverUrl` 指向当前域名，但 Socket 在其它域名/端口 | 使用 `gamedomain=真实Socket域名或IP:端口` |
| 中文昵称异常 | 前端按 `&` 和 `=` 简单拆 query | 中文、空格、特殊字符要 URL 编码 |
